# Asset forge

One stage, one output: **an asset document in the project folder, from which the director generates
every plate the film needs — before a single shot prompt is written.**

Shots are cheap to rewrite. Assets are not: a character's face or a room's layout is referenced by
every shot that uses it, so an asset decided badly costs the whole film. That is why this stage runs
first and stops for approval.

## Inputs

- the script (plot, dialogue, character bios)
- the storyboard (shot table)
- `project-profile.yaml` (style/light band, folder conventions)
- the running inventory: `scripts/extract_assets.py` writes `assets_inventory.md` — characters with
  wardrobe/body-state clues, the scene list, and props ranked by how often the storyboard calls for
  them.

## Outputs — one document, saved to the project folder

`assets_prompts.md` (structure in `templates/asset-prompt-document.md`), containing:

1. **Character assets** — one prompt per *identity* (the face, the body, the standing look), plus a
   **separate prompt for every variant** the story allows: a change of outfit, a change of body
   state (beaten, soaked, bound, bandaged), a change of hair or makeup. Name each variant and list
   the shots it serves, so nobody has to guess which plate to attach.
2. **Scene assets** — for every location, **four directional prompts (N/E/S/W)**: same room, same
   furniture, same fixed facts, four camera positions. Plus a short layout note stating what is on
   each side (which wall the door is on, where the window is, which way the furniture faces), so the
   four views cannot contradict each other.
3. **Prop assets** — one prompt per prop that recurs, with its condition and its standing rule
   ("coiled many times, loose end hanging, not handcuffs"). Props that appear once usually ride along
   inside a scene plate instead.
4. **A generation order** — what to make first (identities → variants → the locations that shoot
   soonest → props), and which plates a given shot will need.

## Rules

- **Every prompt carries the same style/light band, verbatim.** Assets that disagree on palette make
  every later shot a colour-matching problem.
- **A variant is a new prompt, not a note.** "He is soaked in this scene" is not enough: write the
  soaked variant out in full, or the plate will be guessed.
- **Four directions means four prompts that agree.** Write the layout note first, then the four views
  against it; a room whose door moves between views is worse than a room with no reference at all.
- **One prop per prompt, one subject per prompt** for props; a single character per prompt for
  character plates (never two characters in one asset — they contaminate each other).
- **Say what the plate is for.** A plate used only for palette or lighting gets "this image is a
  lighting and palette reference only" written into the prompt that uses it.
- Stop after the document and hand it over. Plates are generated by the director, one by one; the
  document is the checklist that keeps that from drifting.

## After the assets exist

Only then does shot work begin: for each shot id, the crew reads `world_state.yaml` (which variant
is active, what the scene's fixed facts are), and writes the shot prompt against the plates that now
exist. Corrections the director reports are triaged into the crew's skills — see
`skills/virtual-crew/references/feedback-triage.md`.
